## Intro
Si bien no utilizaremos un lenguaje formal para especificar, necesitamos una forma de declarar efectivamente casos a evaluar, algo que nos permita anotar condiciones y evaluaciones de estas mismas.
## Logica Proposicional
- Es la logica que habla sobre las proposiciones.
- Se puede evaluar como una oracion.
- Oraciones con un valor de verdad a ser deducido en base al valor de otras: **Verdadero** (V) o **Falso** (F)
### Simbolos

| Simbolo    | Nombre            | Uso                                |
| ---------- | ----------------- | ---------------------------------- |
| $V$        | Verdadero / True  | Valor de verdad                    |
| $F$        | Falso / False     | Valor de verdad                    |
| $\land$    | Conjuncion        | Evalua "Y" entre variables.        |
| $\lor$     | Disyuncion        | "O" entre variables.               |
| $\neg$     | Negacion          | Invierte el valor de una variable. |
| ( )        | Parentesis        | Contiene una proposicion.          |
| $\implies$ | Implicacion       | "Si... Entonces" entre variables.  |
| $\iff$     | Doble implicacion | "Si y solo si" entre variables.    |
- **Las variables proposicionales**: Infinitas, pueden ser letras sueltas como *a, b, p, q r, ...* 
- **Formulas**
	- True y False son formulas
	- Cualquier variable proposicional es una formula.
	- Si A es una formula, su negacion tambien lo es.
	- Si A1, A2... An son formulas, la conjuncion y la disyuncion de todas ellas lo son.
	- Si A y B son formulas, (A $\implies$ B) y (A $\iff$ B) tambien lo son.
	- Evaluamos entre dos variables a la vez, contenidas en parentesis.

## Lenguaje de Especificacion

```
problema nombre(parametros): tipo de dato del resultado {
	requiere etiqueta: { condiciones sobre los parametros de entrada };
	asegura etiqueta: { condiciones sobre los parametros de salida };
}

```

**nombre**: Nombre que le damos al problema, el cual sera resuelto por una funcion con ese mismo nombre.
**parametros**: lista de parametros separada por comas, donde cada parametro contiene un nombre y un tipo de dato.
**tipo de dato del resultado**: tipo de dato del resultado del problema (inicialmente especificaremos funciones). Desde los asegura, podremos referenciar el valor devuelto con el nombre de *res*.
**etiquetas**: Nombres opcionales que nos serviran para nombrar declarativamente alas condiciones de los requiere o aseguras.
**Tipo de dato**: Conjunto de valores y operaciones que los involucran.

Con este bloque se define el nombre del problema, el tipo de dato que espera del resultado, y los parametros dados. Se aseguran los parametros que otorgan el derecho al programador de esperar un tipo de dato, y se establecen los requisitos que otorgan la obligacion al programador de devolver informacion en una forma.

El programador por ende debera programar y trabajar con contratos que cumplan lo pedido, ni menos **ni mas**, es importante que en el contrato tengamos contingencias que cumplan los casos pedidy operaciones.os, no que perdamos tiempo considerando mas y mas situaciones alternas que no se nos pidan.

**Los requiere**
- Describen las condiciones y posibles valores o casuisticas de los parametros de entrada.
- Puede haber mas de un requiere (se recomienda una condicion por renglon). Se asumen que valen todos juntos (una conjuncion).
- Evitar contradicciones  entre ellos.
**Los asegura**
- Cumpliran lo mismo para los parametros de salida.

### Lenguaje semiformal
Trabajaremos con un lenguaje semiformal, trabajando mas la parte proposicional hasta utilizar logica de primer orden donde esta no cubra.

### El Contrato
El programa escribe un programa P tal que si el usuario suministra datos que hacen verdadera la precondicion, entonces P termina en una cantidad finita de datos retornando un valor que hace verdadera la postcondicion. El programa P es correcto para la especificacion dada por la precondicion y la postcondicion exactamente cuando se cumple el contrato.
